# Samsung UE49NU8079 adaptation

This is the detailed device record for this fork. See [TV status](tv-status.md) for the short current summary and the distinction from the upstream LS03D.

This fork records an owner's tested adaptation of CleanFrame for a Samsung
UE49NU8079, firmware **T-KTM2DEUC-1360.0**, Tizen **4.0**, ARMv7.
Observations below were collected on 29–30 October 2026. They are not a claim of
support for every NU8000 or Tizen 4 TV.

The TV-specific adaptation is an explicit build overlay. The source identity
checks and Tizen 6.5 package declaration remain unchanged; this fork also adds
the configurable [Sources menu](sources.md) in `app/`. Run the separate
builder below to reproduce the adapted package. Ordinary `npm run package`
does not apply this overlay.

## Changes captured

- Generated manifest requests Tizen 4.0 and the owner's own SDK application identity.
- Sources replaces the former direct Live TV control. Its Live TV item selects
  the reported tuner before launching `org.tizen.tv-viewer` for cable TV.
- Prime Video uses the installed `evKhCgZelL.AmazonIgnitionLauncher2` target.
- YouTube keeps its catalogue/preference ID, but the overlay routes launches
  of `9Ur5IzDKqV.TizenYouTube` to the installed `com.samsung.tv.cobalt-yt` entry.
  This also applies after refreshing All apps; saved app choices are unchanged.
- Samsung Home keeps `com.samsung.tv.csfs`; error guidance names Samsung Home.
- An optional local app selection is seeded only when neither current nor legacy
  CleanFrame preferences exist. Updates preserve the saved order and appearance.
- Only public fonts are packaged. Signing and installation remain separate steps.
- TV settings uses an explicit Tizen Settings app control addressed to
  `org.tizen.menu`; a plain application launch caused the focus defect below.

## Observed on this TV

The owner confirmed rendering, app navigation and launches, Live TV, and the
Samsung Home escape. The physical Home button still opens Samsung Home.
The normal Samsung option to resume the last app works; it does not pin
CleanFrame as the startup destination after a different app was used.

**YouTube:** The owner reported that Samsung Home supported long-OK menus,
while the original CleanFrame route attempted playback instead and produced a
black picture or a still frame. Profile selection appeared via both routes on
retest, so a missing profile prompt is not a confirmed distinction. Both
YouTube entries were found in the TV's app list. The owner confirmed long OK
and moving video/audio after a direct SDK launch of `com.samsung.tv.cobalt-yt`.
The overlay now uses that target at the launch boundary. After installing the
update, the owner also confirmed the long-OK menu and moving video with audio
when opening YouTube from the CleanFrame tile. This verifies the workaround on
this TV; the underlying reason for the difference between the two entries has
not been established.

**TV settings before the fix:** Selecting this entry could leave CleanFrame visible while the
direction buttons stop navigating. Home, Guide and Back still work. One Back
press restores CleanFrame navigation. Volume was not tested. Initial reports
described a complete hang and recovery by power off/on; the owner subsequently
corrected the observation. The successful Samsung Home redirection workaround
was removed at the owner's request because it duplicated the existing Home entry.

The earlier overlay called `tizen.application.launch('org.tizen.menu', ...)` without
additional launch data. An input-focus conflict with the internal menu is a
hypothesis, not a diagnosed system cause. Local tests of success, failure,
missing launch callbacks and missing Enter keyup kept direction/Back handling
responsive. Those tests do not emulate Samsung's native menu or input routing.

**Live diagnosis, 30 October 2026:** With the installed CleanFrame opened in
debug mode, temporary in-memory Web Inspector listeners recorded the settings
request, a successful `tizen.application.launch('org.tizen.menu')` callback,
then `window.blur`. CleanFrame remained visibly on screen and
`document.hidden` stayed false, but `document.hasFocus()` became false. A
subsequent Left press and Back press produced no CleanFrame keydown events and
no visible response. Physical Home opened Samsung Home; reopening CleanFrame
restored focus and direction-key navigation. Thus the TV routes input away from
the still-visible launcher after the menu launch. The precise reason the menu
does not draw its UI is still unknown. This run's Back result differs from the
29 October observation above.

The installed-app list contains `org.tizen.menu` but not
`com.samsung.tv.coba.setting`. A read-only `findAppControl` query for Tizen's
documented `http://tizen.org/appcontrol/operation/setting` returned
`NotFoundError` on this TV. This query did not reveal the working explicit
route. No package was installed and no native Home/startup value was changed
during this diagnostic step.

**Follow-up on the same TV:** CleanFrame's Samsung Home action visibly opened
Samsung Home. Opening the TV settings from Samsung Home then showed a usable
menu. After returning to CleanFrame, its direct TV-settings action still left
CleanFrame visible and unresponsive. A prior successful Samsung Home/settings
sequence therefore does not make the direct `org.tizen.menu` launch work. A
running-app-context query listed the same relevant processes before and during
the working menu; it did not identify the foreground window or launch data.

**Fixed direct Settings route, 30 October 2026:** A live Web Inspector test
called `tizen.application.launchAppControl` with operation
`http://tizen.org/appcontrol/operation/setting` and explicit target
`org.tizen.menu`. The owner saw a visible, navigable TV-settings dialog directly
from CleanFrame. The Settings app control is documented by
[Tizen](https://docs.tizen.org/application/web/guides/app-management/common-appcontrols/#system-settings);
the explicit target and visible result are verified only on this TV.
`findAppControl` returning `NotFoundError` did not prevent the explicit call.
The overlay now uses this route and preserves launch errors and the timeout.

A fresh NU8000 build from the current `app/` source was signed with the existing
author certificate and installed in place. The owner confirmed that current
CleanFrame is visible and navigable, and that its TV-settings entry opens a
visible, navigable dialog. Back from that dialog returns to Samsung Home, which
remains usable. Requesting app-control launch mode `GROUP` did not change that
destination, and closing the dialog produced no app-control reply callback.
The earlier plain-launch focus trap is fixed; direct Back-to-CleanFrame is not
supported by the tested route. No native Home/startup value was changed.

## Reproduce an unsigned build

1. Copy `nu8000.example.json` to ignored `.local/nu8000.json`.
2. Replace both identity placeholders with the IDs from your own SDK-generated
   project. Keep the identity and author certificate stable for installed updates.
3. Choose installed app identifiers in `selection.home` (one to nine). Dynamic
   entries also need `{ "id": "APP_ID", "appId": "APP_ID", "name": "App name" }`
   in `selection.appRecords`. Keep your personal selection local.
4. From the repository root run `python scripts/prepare_nu8000.py`.

For a private build with your own Pixabay key, add `--with-online-keys` after
configuring `.local/daily-pictures.json` as described in
[daily pictures](daily-pictures.md). The default omits credentials. Both modes
use public fonts. A widget containing a key must stay private.

The builder prints a fresh ignored folder containing `stage/`, an unsigned
widget and `build.json`. It does not connect to the TV, read certificates, sign,
install, or alter Home/startup settings. Public source alone is insufficient to
update another owner's signed installation.

On Windows, the generated `stage` can be signed with the official SDK CLI:

```powershell
& '<SDK>/tools/ide/bin/tizen.bat' package -t wgt -s '<YOUR_PROFILE>' -o '<NEW_SIGNED_OUTPUT>' -- '<PRINTED_STAGE>'
```

Keep the output local. Use the [setup guide](agent-tv-setup-guide.md) for separate
device installation. On this TV the Samsung distributor certificate had to use
the actual SDB certificate DUID; a network API UUID or a manually typed model/IP
was not a substitute. Device Manager's **Permit to install applications** was
also needed. No certificates, identifiers, IPs or signed packages are in this fork.

## Local validation

Run `python scripts/test_nu8000.py` for overlay and package checks. Run the
upstream lint, source, device and public-source checks as documented. The
upstream `check:tools` suite imports POSIX `termios` and cannot run on native
Windows; this does not mean it passed. Browser checks do not establish native
TV-menu compatibility.
